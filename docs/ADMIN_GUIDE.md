# 관리자 사용 안내

## 로그인

로컬은 `http://127.0.0.1:4173/admin/`, 운영은 홈페이지 주소 끝에 `admin/`을 붙입니다. 로컬 비밀번호는 `.env`의 `ADMIN_PASSWORD`, 운영은 Worker Secret 값입니다.

로그인은 8시간 유지되며 새로고침하면 메모리 토큰이 사라져 재로그인이 필요합니다. 비밀번호를 바꾸면 기존 세션도 사용할 수 없습니다. 로그인이 반복해서 실패하면 15분 후 다시 시도하세요.

## 홈페이지와 같은 관리 메뉴

관리 메뉴는 **Works → Exhibition → Texts → CV** 순서입니다. 각 메뉴의 **이 페이지 보기**로 방문객 화면을 확인할 수 있습니다.

- **Works**: 작품 이미지·작품명·연도·재료·크기·설명
- **Exhibition**: 전시 정보·대표 이미지·사진 갤러리·작품 연결. 소식은 이 메뉴 아래의 **소식 관리**에서 등록합니다.
- **Texts**: 작가 노트와 작업 관련 글
- **CV**: 작가 소개·사진·연락처·약력·CV PDF

## 작가 소개와 글

CV에서 이름·영문명·분야·소개를 입력하고, Texts에서 작가 노트와 작업 관련 글을 편집합니다. 작가 사진과 CV PDF는 선택 사항입니다. 이메일이 없으면 연락 링크가 표시되지 않습니다. Instagram은 전체 주소 대신 사용자 이름만 입력합니다.

홈 배경은 항상 흰색입니다. 작품 이미지는 작품 탭에서 업로드·수정·삭제하고 게시하면 홈과 Works에 반영됩니다. 모든 화면에서 작품의 원래 비율을 유지합니다.

홈은 관리자에서 정한 순서대로 PC와 모바일 모두 이미지를 한 점씩 크게 보여 줍니다. 작품명·연도·페이지 번호·하단 조작 버튼은 기본 화면에 표시하지 않습니다. 작품이 두 점 이상이면 약 5초마다 한 점씩 순환하며, 마우스를 올려도 계속 움직입니다. 키보드로 작품에 초점을 두거나 다른 브라우저 탭으로 이동하면 잠시 멈춥니다. 키보드 Tab으로 접근할 때는 일시정지·재생 버튼이 나타납니다. 기기의 동작 줄이기 설정을 사용하면 슬라이드 효과 없이 다음 이미지로 교체합니다. 작품을 누르면 `work.html?id=작품ID` 상세 페이지에서 제목·연도·재료·크기·설명을 확인할 수 있습니다. 홈 이미지는 화면 높이에 맞춰 크게 표시하고, Works는 작은 썸네일 그리드를 사용합니다.

작가 노트·작업 관련 글은 Texts, 작품은 Works, 전시·소식은 Exhibition, 작가 소개·사진·약력·연락처는 CV에 반영됩니다. 홈페이지 하위 페이지의 Admin 링크나 `/admin/` 주소로 관리자에 접근할 수 있습니다.

홈 이미지의 왼쪽·오른쪽 가장자리에 마우스를 올리면 흐릿한 `<`·`>` 버튼이 나타납니다. 클릭하면 이전·다음 작품으로 이동하며 마지막과 첫 작품이 이어집니다. 키보드 Tab으로 버튼에 초점을 두어도 표시되고, 터치 화면에서는 양쪽 영역을 눌러 이동할 수 있습니다. 수동 이동 후에는 자동 순환 대기 시간이 다시 시작됩니다.

## 작품 등록

1. **Works → 작품 추가**를 누릅니다.
2. JPG·PNG·WebP·TIF·TIFF 이미지를 선택합니다. 원본 파일 용량 제한 없이 긴 변 최대 2,400px의 WebP로 변환하며 비율을 유지합니다. 변환된 업로드 파일은 최대 5MB입니다. 큰 원본은 기기의 메모리와 브라우저가 처리할 수 있는 범위에서 변환됩니다. TIFF는 브라우저에서 변환한 뒤 업로드하고, 여러 페이지가 있으면 첫 페이지만 사용합니다. TIFF 원본은 별도로 보관하세요.
3. 작품명·4자리 연도를 입력합니다. 재료·크기·대체 설명·소개도 입력할 수 있습니다.
4. 위·아래 버튼으로 표시 순서를 정합니다. Works는 최신 연도부터 구분선과 함께 묶어 표시하며, 같은 연도 안에서는 이 순서를 따릅니다. 작품 아래에는 제목·재료·크기만 표시하고 연도는 구분 제목에 표시합니다.
5. **변경사항 게시**를 누릅니다.

변환된 이미지와 PDF는 파일당 최대 5MB입니다. 업로드 완료 시 파일은 이미 저장소(로컬에서는 디스크)에 저장됩니다. 게시 전에는 작품 목록에 연결되지 않습니다. **업로드 공간은 비공개 초안 저장소가 아니므로 공개 가능한 파일만 올립니다.**

TIFF는 최대 4천만 화소, 한 변 16,384px까지 변환합니다. 일반 RGB·그레이스케일 TIFF와 지원되는 압축 형식을 처리하며, BigTIFF·분리 채널·부동소수점 등 지원하지 않는 저장 형식은 안내 메시지를 표시합니다. 이 경우 일반 RGB TIFF 또는 PNG로 다시 저장해 주세요. 작가 사진에도 같은 업로드 형식을 사용할 수 있습니다.

## 약력·전시·소식

- 약력: 구분(학력·개인전·단체전·수상 등), 기간, 내용. 같은 구분끼리 표시됩니다.
- 전시: 개인전·단체전 구분을 선택하고 전시명·4자리 연도·장소·소개를 입력합니다. Exhibition 페이지에서 구분을 선택하면 Works와 같은 중앙 정렬 이미지 그리드를 최신 연도부터 구분선과 함께 표시합니다. 같은 구분과 연도 내 순서는 관리자의 위·아래 버튼으로 조정합니다. 예전 데이터에 구분이 없으면 임의로 분류하지 않고 미분류로 보존하므로, 관리자에서 구분을 선택해 게시하세요.
- 소식: 제목·날짜·본문. 빈 줄로 문단을 구분합니다.

전시명 입력을 마치고 다른 항목으로 이동하면 자동으로 `《제목》` 형태가 됩니다. 이미 `《》`를 입력했다면 중복해서 붙이지 않으며, 제목 안에 다른 괄호도 사용할 수 있습니다.

### 전시 사진과 상세 페이지

1. 전시의 **사진 여러 장 추가**에서 포스터·전시장·작품 사진을 선택합니다. 대표 이미지는 필수이며 전시당 최대 50장까지 등록합니다. JPG·PNG·WebP·TIF·TIFF를 지원합니다. 작품 업로드와 동일하게 WebP로 최적화합니다.
2. 사진의 **대표 사진으로 설정**을 누릅니다. 전시 목록과 상세 페이지를 처음 열 때 이 사진이 표시됩니다.
3. 사진마다 **연결할 Works 작품**을 선택할 수 있습니다. 연결된 큰 사진을 클릭하면 해당 작품 상세 페이지로 이동합니다. 일반 전시장 사진은 **연결 안 함**으로 둡니다.
4. 위·아래 버튼으로 사진 순서를 바꾸고, 사진 설명을 입력하거나 **사진 삭제**로 제거합니다. 대표 사진을 삭제하면 남은 첫 사진이 대표가 됩니다. Works 작품을 삭제하면 전시 사진은 유지하고 작품 연결만 해제합니다.
5. 전시 기간·장소·**전시 소개 (+ Info)**를 입력하고 **변경사항 게시**를 누릅니다.

방문객은 Exhibition 목록의 전시명이나 대표 사진을 눌러 상세 페이지로 들어갑니다. 상세 화면의 제목은 해당 전시명입니다. 사이드바 없이 왼쪽에는 전시 정보와 썸네일, 오른쪽에는 큰 사진이 표시됩니다. 썸네일·좌우 화살표로 사진을 바꾸고 **+ Info**로 소개를 열어봅니다. 모바일에서는 세로로 배치됩니다.

기존 대표 사진은 사진 목록의 첫 항목으로 이어집니다. 대표 이미지가 없으면 게시할 수 없습니다. 기존에 사진 없이 등록한 전시도 다음 게시 전에 사진을 추가해 주세요. 여러 장 중 업로드가 실패하면 완료된 사진은 유지되므로 나머지 파일만 다시 선택하세요.

HTML 서식 편집은 제공하지 않습니다. 글은 일반 텍스트로 표시합니다.

## 저장과 삭제

글은 자동 저장되지 않습니다. 탭 이동 시 유지되지만 새로고침하면 사라집니다. 저장하지 않고 떠나면 브라우저 경고가 나타납니다.

운영에서 게시하면 GitHub 커밋 후 Actions가 배포합니다. 보통 1~3분 정도 걸릴 수 있으며 대기열에 따라 더 길어질 수 있습니다. 저장 성공과 배포 성공은 별개입니다. 오래 반영되지 않으면 Actions의 `Deploy GitHub Pages` 결과를 확인합니다.

항목 삭제는 확인창을 거쳐 진행하며 **변경사항 게시**로 적용합니다. 업로드 파일과 커밋 이력은 자동 삭제하지 않습니다. 실수로 지운 내용은 Git 이력에서 복구할 수 있습니다.

## 문제 해결

| 증상 | 확인 |
| --- | --- |
| 관리자 연결 준비 중 | GitHub Actions 변수 `ADMIN_API_URL` 등록 후 재배포 |
| 비밀번호·인증 저장소 설정 필요 | `.env`, Worker Secret, D1 바인딩·마이그레이션 |
| 로그인 만료 | 새로고침 없이 재로그인하면 작성 중 내용 유지 |
| 다른 변경사항과 충돌 | 글을 별도로 보관하고 새로고침해 최신 내용에 다시 반영 |
| GitHub 저장 실패 | 토큰 만료·Contents 권한·브랜치 보호·API 한도 |
| 저장 후 화면 그대로 | Actions 결과 확인 후 홈페이지 새로고침 |
| 로컬과 운영 변경 충돌 | `git pull --rebase`로 최신 변경을 통합 |

이미지 변환 시 원본 색상 프로파일·메타데이터가 보존되지 않을 수 있습니다. 인쇄용 원본은 따로 보관하고 변환 후 홈페이지의 색감과 디테일을 직접 확인하세요.
